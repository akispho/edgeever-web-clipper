# Obsidian Clipper → EdgeEver 适配设计

## 目标与已确认的选择

用户希望完整保留 Obsidian Clipper 的界面、功能和内容剪藏效果，最终内容存入 EdgeEver。使用当前已下载的 Obsidian Clipper 源码作为基础；EdgeEver 源码及用户提供的 0.3.0 扩展仅供协议和行为对照。

## 方案

1. **采用：适配 Obsidian Clipper 的保存端。** 保留抽取、Markdown 转换、模板、变量、过滤器、属性、划线、阅读模式、侧栏、快捷剪藏、复制和下载功能。开发 EdgeEver API 适配及目的地设置。理由：满足用户明确选择，且避免重写剪藏核心。
2. 不采用：在 EdgeEver 原扩展中替换抽取引擎。维护范围较小，但不能提供用户希望保留的完整界面及功能。
3. 不采用：通过 Obsidian 本地仓库再同步。需要额外应用和同步链路，不能直接保存进 EdgeEver。

## 保存语义：用户已确认

EdgeEver 的 resources 接口管理笔记所属的附件；它与可直接阅读编辑的笔记不是同一对象。

- 创建可阅读编辑的 Markdown 笔记，图片进入笔记附件库；保留模板生成的属性和来源。
- 不额外生成或上传整篇 .md 附件，保留原扩展的手动下载功能。

## 界面和功能映射

- 沿用原布局、组件和交互；更换产品名称与自制图标，保留 MIT 版权声明，不冒充 Obsidian 官方扩展。
- 增加 EdgeEver 实例地址、API Token、连接测试；Token 仅在扩展本地保存，不进入同步存储、导出、日志或网页内容脚本。
- 原仓库选择映射为 EdgeEver 笔记本；路径映射为其子笔记本。按 ID 保存绑定；重名与失效绑定必须明确提示，不能随意写入另一个目录。
- 模板创建、指定笔记追加/前插、覆盖、日记追加/前插分别适配 EdgeEver；日记按用户本地日期命名。只在明确指定目标时更新已有笔记，存在多个同名目标时中止并提示。
- 原 Obsidian 专用设置必须替换为有效的 EdgeEver 行为或明确说明不适用，不能保留无效控件假装兼容。
- 所有保存入口汇入统一适配器，包括弹窗、侧栏和快捷剪藏。保留复制、下载及模板导入导出。
- AI 整理沿用原可选功能及原服务设置，不自动开启或向模型服务发送内容。

## 已核对的 API 与约束

- `GET /api/v1/notebooks`：读取笔记本；子笔记本通过 parentId 组织。
- `POST /api/v1/memos`：创建笔记，字段包括 notebookId、title、contentMarkdown、tags。
- `GET /api/v1/memos/:id`、`POST /api/v1/memos/:id/edit-sessions`、保存接口：更新前读取最新内容并使用编辑会话，发生冲突不得覆盖用户编辑。
- `POST /api/v1/memos/:id/resources`：上传关联附件。
- `GET /api/v1/resources/:id/blob`：附件引用；`GET /api/v1/resources`：附件库。
- 请求使用 Bearer Token；必须验证目的地 URL，仅向配置的实例发送认证头，拒绝跨源认证重定向。
- 图片下载不携带 EdgeEver Token；失败图片保留来源并给出部分成功提示。限制大小、数量和超时，不能静默丢失正文或图片。

## 范围、风险和恢复

改动限于独立扩展：目的地设置、保存适配、对应入口、文案、品牌、构建及测试；正文提取与模板语法沿用上游。不修改 EdgeEver 服务端，不替换用户现用扩展，不自动写入真实笔记。

主要风险为图片源限制、服务端版本差异、同名目标及并发编辑。先验证请求契约、冲突和失败路径，再在用户指定实例中执行获授权的测试。卸载此独立扩展可恢复原工作流；不能用永久删除笔记作为上传失败的自动回滚方式。

## 验证与交付

- 运行上游测试、类型检查及 Chromium 构建；针对新增的保存、图片替换、Token 隔离、目标歧义和并发冲突加入测试。
- 使用包含标题、列表、表格、代码、链接、图片和划线的页面检查预览与保存结果；核对快捷剪藏和侧栏保存入口。
- 优先交付 Edge/Chrome 可加载目录和 ZIP、源码、中文安装说明及已验证/未验证功能清单。Firefox/Safari 功能沿用不等于已通过平台验收；分别说明实际测试范围。
- 真实实例验收需要实例地址及用户自行配置的 Token；不在聊天或文档中保存凭据。

## 当前状态

完成源码和接口勘察；用户已确认保存为可阅读编辑的笔记和图片附件。用户已批准设计并授权实现。开发预览版已实现，自动化检查通过；真实实例保存仍未验收，详见 VALIDATION.md。

## 实施顺序与实现者可自行决定的事项

1. 保留上游源码快照和现有测试，确定独立扩展标识及品牌资源。
2. 实现 EdgeEver 连接设置、目标笔记本与路径映射；实例地址和 Token 在运行时由用户配置。
3. 接入统一笔记创建、更新和图片上传流程，覆盖各保存入口及模板行为。
4. 完成失败提示、并发冲突保护、构建和安装文档。
5. 执行自动化与浏览器验收，真实实例测试等待用户配置并授权。

实现者自行决定：模块划分、测试 fixture、独立扩展名称和图标细节、合理的附件传输上限、无需用户登录的本地验证方式。部署版本未给出时，以已下载 API 源码为开发基线；不宣称支持未经验证的旧版实例。原有文件路径映射为子笔记本；不存在的目录可按模板创建，权限不足则明确提示。新增权限及平台未支持的专用能力须在安装说明中列出。
