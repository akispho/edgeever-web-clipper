# 安装与配置

## Edge / Chrome

从构建产物 ZIP 解压到固定目录，打开 `edge://extensions` 或 `chrome://extensions`，开启开发者模式，点击“加载解压缩的扩展”，选择直接包含 `manifest.json` 的文件夹。不要选择 ZIP 本身。

这是独立的社区扩展，可以与原 Obsidian Clipper 并存；快捷键相同可能冲突，可在浏览器的扩展快捷键页面修改。原 EdgeEver 扩展的配置和浏览器 ID 不会被覆盖。

## 连接 EdgeEver

在 EdgeEver 的 API / MCP 设置中生成 API Token。在扩展设置里填写完整实例地址，例如 `https://notes.example.com`。如部署在子路径，填写 `https://example.com/notes`，不要追加 `/api/v1`、用户名、密码、查询参数或锚点。

需要读取笔记本和笔记、写入笔记与附件的权限：`read:notebooks`、`read:memos`、`write:memos`、`write:resources`；要按模板路径创建子笔记本，还需要 `write:notebooks`。你的 EdgeEver 版本若使用不同的权限组合，请以实例的 Token 页面为准。

输入 Token，点击“连接并保存”。选定默认笔记本后再次保存。Token 输入框留空表示沿用当前实例的已有 Token；更换实例地址时必须输入新 Token。

界面不会回显已有 Token。Token 保存在当前浏览器配置的扩展 IndexedDB 中，不随模板/设置导出；重装扩展或清除扩展数据后需要重新配置。

## 剪藏

打开文章，点击扩展，使用原有模板、变量、划线和内容编辑能力；预览确认后保存到 EdgeEver。目录字段按 `/` 分割成子笔记本。模板目的地使用 EdgeEver 笔记本 ID，导入 Obsidian 模板后需重新选择。

“创建”总是新建笔记；追加/前插/覆盖只在所选笔记本内匹配完全同名的目标。目标不存在会新建；同名目标超过一个会中止。日记模板按当前设备的日期生成 `YYYY-MM-DD` 标题。

覆盖模板会替换目标全文，这是显式行为。若目标只有富文本 contentJson 而 Markdown 为空，追加/前插会中止以保护原文，请先在 EdgeEver 中转换或改用新建。追加、前插、覆盖及图片链接替换都使用 EdgeEver 编辑会话和版本校验；发生冲突时请打开 EdgeEver 检查后重试。

图片保存失败或超限时保留原始地址。提示部分成功时，正文已经保存，不要以“创建”模式反复点击，否则会生成多篇笔记。已上传但未能替换链接的图片仍可能出现在笔记附件中。

## 排错与边界

- HTTP 401/403：检查 Token、权限和实例地址。
- HTTP 409：笔记发生变化；不会自动覆盖其他客户端的编辑。
- 连接失败：检查 TLS、反向代理、Cloudflare Access 或登录挑战；认证请求不会跟随重定向。
- 页面预览正常但图片未复制：图片源可能要求 Cookie、跳转或限制扩展访问，当前版本保留原链接。
- 笔记本失效或同名路径：重新连接并在模板里指定唯一笔记本。
- Firefox 未完成验收；Safari 本地 App 包装不在此版本交付范围。

自动化测试验证的是模拟接口契约和本地构建，不代表已在你的实例中成功剪藏。首次使用建议在测试笔记本中剪藏一篇有表格、代码和图片的文章，核对显示后再日常使用。
